🧮 Module 1

🧱 DP Foundations

Why does Dynamic Programming exist? What problems does it solve? How is it different from recursion, greedy, and divide & conquer?

🧠 One-sentence definition

Dynamic Programming = Recursion + Memoization.
If a recursive solution recomputes the same subproblem multiple times, store the result and reuse it. That's the entire idea.

The Problem with Pure Recursion

Consider computing fib(5). The recursive call tree looks like this: 

                    fib(5)
                   /       \
             fib(4)         fib(3)  ← recomputed!
            /      \        /    \
       fib(3)    fib(2)  fib(2) fib(1)
       /    \    /    \
   fib(2) fib(1) fib(1) fib(0)
   /    \
fib(1) fib(0)

fib(3) is called 2 times
fib(2) is called 3 times      → T(n) = O(2ⁿ) without memoization
fib(1) is called 5 times      → T(n) = O(n)   WITH memoization
Two Conditions for DP
1️⃣ Overlapping Subproblems

The same subproblem appears more than once in the recursion tree.

How to spot: Draw a small call tree. Do the same arguments appear at multiple nodes?

fib(3) called twice → YES → DP will help.

2️⃣ Optimal Substructure

The optimal answer to the full problem can be built from optimal answers to smaller subproblems.

How to spot: "If I knew the best solution for input of size n-1, could I compute it for size n?"

If yes → optimal substructure exists.

Three Approaches to DP
// Fibonacci — Pure Recursion   Time: O(2ⁿ)   Space: O(n) stack
int fib(int n) {
    if (n <= 1) return n;              // base case
    return fib(n-1) + fib(n-2);       // recomputes same subproblems!
}
// Fibonacci — Memoization (Top-Down DP)   Time: O(n)   Space: O(n)
int[] memo = new int[n+1];
Arrays.fill(memo, -1);

int fib(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];   // cache hit — return stored
    return memo[n] = fib(n-1) + fib(n-2); // store THEN return
}
// Each subproblem computed EXACTLY once → O(n) time
// Fibonacci — Tabulation (Bottom-Up DP)   Time: O(n)   Space: O(n)
int fib(int n) {
    if (n <= 1) return n;
    int[] dp = new int[n+1];
    dp[0] = 0;  dp[1] = 1;           // base cases
    for (int i = 2; i <= n; i++)
        dp[i] = dp[i-1] + dp[i-2];   // fill bottom-up
    return dp[n];
}
// No recursion overhead. Easier to space-optimise.
// Fibonacci — Space Optimised   Time: O(n)   Space: O(1)
int fib(int n) {
    if (n <= 1) return n;
    int a = 0, b = 1;
    for (int i = 2; i <= n; i++) {
        int c = a + b;
        a = b;
        b = c;
    }
    return b;
}
// Only need previous 2 values → drop the array entirely

✅ Key Takeaway

Before applying DP, ask: "If I solve this recursively, do I re-solve the same subproblem?" If yes → DP. The memo table is just a cache. The recurrence is just the recursion written differently. Always start with the recursive brute force. That makes the DP natural.
