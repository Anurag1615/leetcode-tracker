⚠️ Common Mistakes

8 mistakes that cause 80% of DP bugs. Read carefully — most interview failures come from these.

📋 How to use this page

For each mistake: read the WRONG code, understand WHY it fails, then read the fix. Then do one problem from that pattern to confirm you won't repeat the mistake.

Mistake 1 — Wrong iteration direction (0/1 vs Unbounded)
❌ Bug: Forward loop for 0/1 knapsack allows item reuse

When you iterate forward, dp[w-wt[i]] was already updated in this same pass — meaning you can pick the same item multiple times.

// WRONG — forward loop for 0/1 knapsack
for (int i = 0; i < n; i++)
    for (int w = wt[i]; w <= W; w++)   // ← FORWARD: unbounded behaviour!
        dp[w] = Math.max(dp[w], dp[w-wt[i]] + val[i]);
// dp[w-wt[i]] already updated in this loop → item i picked multiple times
// CORRECT — reverse loop for 0/1 knapsack
for (int i = 0; i < n; i++)
    for (int w = W; w >= wt[i]; w--)  // ← REVERSE: each item once
        dp[w] = Math.max(dp[w], dp[w-wt[i]] + val[i]);
// dp[w-wt[i]] not yet updated in this pass → item i used at most once
// Rule: REVERSE = 0/1, FORWARD = unbounded
Mistake 2 — Using 0 as memo sentinel when 0 is a valid answer
❌ Bug: false cache hit returns 0 before it's computed
int[] memo = new int[n];  // ← initialized to 0!
int solve(int i) {
    if (i == n) return 0;
    if (memo[i] != 0) return memo[i];  // BUG: 0 is a valid return value!
    // When solve(i) legitimately returns 0, next call returns 0
    // from cache BEFORE it's actually computed
    ...
}
int[] memo = new int[n];
Arrays.fill(memo, -1);  // ← -1 is never a valid answer for most problems
int solve(int i) {
    if (i == n) return 0;
    if (memo[i] != -1) return memo[i];  // safe sentinel
    ...
    return memo[i] = result;
}
// If -1 IS a valid answer, use a separate boolean[] computed array
Mistake 3 — Not copying mutable collections before adding to result
void backtrack(List<Integer> path, ...) {
    if (/* base case */) {
        result.add(path);  // ← adds REFERENCE, not copy!
        return;           // path will be modified later → all results corrupted
    }
    ...
}
void backtrack(List<Integer> path, ...) {
    if (/* base case */) {
        result.add(new ArrayList<>(path));  // ← copy the list
        return;
    }
    ...
}
// Always copy mutable objects before storing them
Mistake 4 — Off-by-one in dp table size
// For Fibonacci(n), need dp[0..n] → size n+1
int[] dp = new int[n];   // ← ArrayIndexOutOfBoundsException at dp[n]!
dp[0] = 0; dp[1] = 1;
for (int i = 2; i <= n; i++)  // i reaches n → dp[n] out of bounds
    dp[i] = dp[i-1] + dp[i-2];
int[] dp = new int[n + 1];  // ← indices 0 through n inclusive
dp[0] = 0; dp[1] = 1;
for (int i = 2; i <= n; i++)
    dp[i] = dp[i-1] + dp[i-2];
// Rule: if dp[n] is the answer, allocate n+1.
// For Knapsack: dp[W+1]. For LCS: dp[m+1][n+1].
Mistake 5 — House Robber II: running rob() only once on circular array
// Wrong: treats circular array as linear
int rob(int[] nums) {
    return robLinear(nums, 0, nums.length-1);
    // BUG: houses 0 and n-1 are adjacent in circular array!
    // If we rob both, constraint is violated
}
// Correct: run robLinear twice, exclude one endpoint each time
int rob(int[] nums) {
    int n = nums.length;
    if (n == 1) return nums[0];
    return Math.max(
        robLinear(nums, 0, n-2),   // exclude last house
        robLinear(nums, 1, n-1)    // exclude first house
    );
}
// Houses 0 and n-1 can never BOTH be robbed → split into 2 subproblems
Mistake 6 — Wrong operator for "count ways" vs "min/max" vs "exists"
// Same recurrence structure, different operator — mixing them gives wrong answer

// COUNT WAYS → use += (accumulate all possibilities)
dp[i] += dp[i - coin];   // Coin Change II — count combinations

// MIN/MAX → use Math.min / Math.max
dp[i] = Math.min(dp[i], dp[i - coin] + 1);  // Coin Change — min coins

// EXISTS (boolean) → use |= (OR)
dp[i] |= dp[i - num];    // Subset Sum — can we reach sum i?

// COMMON MISTAKE: using += for min/max or Math.min for count
Mistake 7 — Combination Sum IV loop order (combinations vs permutations)
// LC 518 Coin Change II — UNORDERED combinations
// Coins OUTER loop → each coin processed independently
for (int coin : coins)
    for (int j = coin; j <= amount; j++)
        dp[j] += dp[j - coin];
// [1,2] and [2,1] counted as ONE combination
// LC 377 Combination Sum IV — ORDERED permutations
// Amounts OUTER loop → all coins tried for each target
for (int j = 1; j <= target; j++)
    for (int coin : coins)
        if (j >= coin) dp[j] += dp[j - coin];
// [1,2] and [2,1] counted as TWO permutations
Mistake 8 — Burst Balloons: choosing first burst instead of last burst
// WRONG: choose k as the FIRST balloon to burst in [i,j]
dp[i][j] = max over k: dp[i][k-1] + nums[k]*neighbours + dp[k+1][j]
// BUG: after bursting k, the neighbours of dp[i][k-1] and dp[k+1][j]
// change! The subproblems are NOT independent.
// CORRECT: choose k as the LAST balloon to burst in [i,j]
dp[i][j] = max over k: dp[i][k-1] + nums[i-1]*nums[k]*nums[j+1] + dp[k+1][j]
// When k is last, boundaries (i-1) and (j+1) are still present!
// So dp[i][k-1] and dp[k+1][j] are truly independent subproblems.
// Add sentinel balloons: nums[-1] = nums[n] = 1
✅ Checklist before submitting any DP solution

□ 0/1 knapsack: inner loop is REVERSE?
□ Memo sentinel is -1 (not 0) when 0 is a valid answer?
□ Adding lists to result: using new ArrayList<>(path)?
□ dp table size: n+1 not n, W+1 not W, (m+1)×(n+1) not m×n?
□ Circular array problem: running twice?
□ Count ways vs min/max: using correct operator (+= vs Math.min)?
□ Combination vs permutation: correct loop order?
