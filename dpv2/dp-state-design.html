🧮 Module 5

🎛️ DP State Design

The most underrated DP skill. Not the recurrence — defining what dp[i] means. Master this and any new problem becomes solvable.

🎯 Why state design matters

Most beginners can write the recurrence once they see it. The hard part is figuring out what information to track. Too little → can't make optimal decisions. Too much → exponential state space. The right state is the minimum information needed.

The 3 Questions to Find Your State
What changes between recursive calls?
List all parameters that change between calls. Those are your state dimensions.

House Robber: only index i changes → 1D: dp[i]
LCS: both i (position in s1) and j (position in s2) change → 2D: dp[i][j]
Stocks with k txns: day, k, holding change → 3D: dp[day][k][hold]
Bitmask DP: mask (set of visited nodes) changes → dp[mask][last]
What affects future decisions?
Only include information in the state that is necessary to make optimal choices going forward. If you can compute the optimal answer from here WITHOUT knowing some piece of history, exclude it.

Knapsack: need remaining capacity w — it limits what items you can still take
House Robber: do NOT need "how I got here" — only current index matters
Stock cooldown: need holding flag — can't buy if already holding
LCS: need both string positions — current chars at both positions determine the choice
Write dp[state] = ... in plain English
This is your function definition. Once you can write this sentence clearly, the recurrence writes itself.

dp[i] = max money robbing houses i through n-1
dp[i][w] = max value using first i items with remaining capacity w
dp[i][j] = LCS length of s1[0..i-1] and s2[0..j-1]
dp[day][hold] = max profit on day, given whether holding stock

Worked Examples — Deriving State Step by Step
// Coin Change — LC 322
// Q1: What changes? → remaining amount (after picking a coin)
// Q2: What affects future? → only rem. Once I pick a coin,
//     only the remaining amount determines future choices.
// Q3: dp[rem] = min coins to make exactly amount rem

// Derivation:
//   at each step I pick one coin c → rem becomes rem-c
//   dp[rem] = 1 + min over all valid coins: dp[rem-coin]
//   base: dp[0] = 0  (0 coins to make 0)
//   impossible sentinel: dp[i] = amount+1 means "can't make i"

int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);   // sentinel: impossible
    dp[0] = 0;                     // base case
    for (int rem = 1; rem <= amount; rem++)
        for (int coin : coins)
            if (coin <= rem)
                dp[rem] = Math.min(dp[rem], dp[rem-coin] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
}
// Stock with Cooldown — LC 309
// Q1: What changes? → current day AND current state
// Q2: What affects future? → whether I'm holding, just sold, or resting
//     (can't buy right after selling → need cooldown state)
// Q3: 3 states per day:
//   hold  = max profit if I'm currently holding stock
//   sold  = max profit if I just sold today (enter cooldown)
//   rest  = max profit if I'm in cooldown/idle (can buy next)

// Transitions (state machine):
//   hold_new  = max(hold, rest - price)   // keep holding OR buy from rest
//   sold_new  = hold + price              // sell: was holding
//   rest_new  = max(rest, sold)           // stay resting OR cooldown after sell

// Why prevSold? sold is updated BEFORE rest reads it
// so we save the old sold value first

int maxProfit(int[] prices) {
    int hold = Integer.MIN_VALUE, sold = 0, rest = 0;
    for (int price : prices) {
        int prevSold = sold;
        sold = hold + price;
        hold = Math.max(hold, rest - price);
        rest = Math.max(rest, prevSold);
    }
    return Math.max(sold, rest);
}
// LCS — LC 1143
// Q1: What changes? → i (position in s1) AND j (position in s2)
// Q2: What affects future? → both positions. Current characters
//     at s1[i] and s2[j] determine whether we match or skip.
// Q3: dp[i][j] = LCS of s1[0..i-1] and s2[0..j-1]

// Derivation:
//   if s1[i-1] == s2[j-1]: this char is in LCS → dp[i][j] = dp[i-1][j-1] + 1
//   else: skip from s1 OR skip from s2, take better
//         dp[i][j] = max(dp[i-1][j], dp[i][j-1])
//   base: dp[0][j] = 0 (empty s1) and dp[i][0] = 0 (empty s2)

// Space optimisation: dp[i] only needs dp[i-1] row.
// Save diagonal dp[i-1][j-1] in variable 'prev'.

int lcs(String s1, String s2) {
    int m = s1.length(), n = s2.length();
    int[] dp = new int[n+1];
    for (int i = 1; i <= m; i++) {
        int prev = 0;              // saves dp[i-1][j-1]
        for (int j = 1; j <= n; j++) {
            int temp = dp[j];
            dp[j] = s1.charAt(i-1)==s2.charAt(j-1) ? prev+1
                  : Math.max(dp[j], dp[j-1]);
            prev = temp;
        }
    }
    return dp[n];
}
// 0/1 Knapsack
// Q1: What changes? → item index i AND remaining capacity w
// Q2: What affects future? → BOTH matter.
//     Which items remain (i) determines choices.
//     Remaining capacity (w) determines which can fit.
// Q3: dp[i][w] = max value using first i items with capacity w

// Derivation:
//   for each item i, two choices:
//   skip: dp[i][w] = dp[i-1][w]
//   take (if wt[i] <= w): dp[i][w] = val[i] + dp[i-1][w-wt[i]]
//   base: dp[0][w] = 0 (no items) and dp[i][0] = 0 (no capacity)

// Space opt: 1D array with REVERSE inner loop
// Reverse prevents item from being used twice in same pass

int knapsack(int[] wt, int[] val, int W) {
    int[] dp = new int[W+1];
    for (int i = 0; i < wt.length; i++)
        for (int w = W; w >= wt[i]; w--)  // REVERSE = 0/1
            dp[w] = Math.max(dp[w], dp[w-wt[i]] + val[i]);
    return dp[W];
}
// Burst Balloons — LC 312 (Hard state design)
// Naive: dp[i][j] = max coins bursting balloons i..j
//        choose k as FIRST balloon → subproblems NOT independent!
//        (k's neighbours change after bursting → can't reuse dp[i][k-1])

// Key insight: think of k as LAST balloon burst in [i,j]
// When k is last, boundaries i-1 and j+1 are still present
// → left part [i..k-1] and right part [k+1..j] are independent!
// Q3: dp[i][j] = max coins bursting all balloons BETWEEN boundaries i and j
//               (boundaries i and j are NOT burst, they're the sentinels)

// Add sentinel balloons: nums[-1] = nums[n] = 1

int maxCoins(int[] nums) {
    int n = nums.length;
    int[] a = new int[n+2];
    a[0] = a[n+1] = 1;
    for(int i=0;i<n;i++) a[i+1]=nums[i];
    int[][] dp = new int[n+2][n+2];
    // Fill by increasing length of range
    for(int len=1;len<=n;len++)
        for(int i=1;i+len-1<=n;i++) {
            int j = i+len-1;
            for(int k=i;k<=j;k++)
                dp[i][j] = Math.max(dp[i][j],
                    dp[i][k-1] + a[i-1]*a[k]*a[j+1] + dp[k+1][j]);
        }
    return dp[1][n];
}
State Reduction — Dropping Dimensions
💡 Always try to reduce after getting the correct solution

Ask: "Does dp[i] really need to know all of dp[i-1], or just part of it?"
If dp[i] only depends on dp[i-1] → 1D array. If dp[i] only depends on dp[i-1] and dp[i-2] → two variables.
