The IBH Method — Induction, Base, Hypothesis. Never start with the DP table. Write the recursive solution first, every single time.

📐 IBH Method (Induction-Base-Hypothesis)

This is Pepcoding's framework. It works for 95% of DP problems.
H → I → B is the thinking order. B → H → I is the coding order.

The Three Steps
Hypothesis — What does solve(n) RETURN?
Define your function in one English sentence. Don't think about how yet — just what.

rob(i) → returns max money robbing from house i to the end
lcs(i, j) → returns LCS length of s1[0..i] and s2[0..j]
knapsack(i, w) → returns max value using first i items with capacity w

This sentence IS your state definition.
Induction — How do I get solve(n) from solve(n-1)?
Assume solve(n-1) works correctly. How do I use it to compute solve(n)?
This is your recurrence relation — the heart of the DP.

House Robber: two choices at house i:
  • Rob house i → nums[i] + rob(i+2) (skip i+1)
  • Skip house i → rob(i+1)
→ rob(i) = max(nums[i] + rob(i+2), rob(i+1))
Base Case — Smallest input you can answer directly
What is the answer when there's nothing left to process?

House Robber: rob(n) = 0 (no houses left)
LCS: lcs(-1, j) = 0 and lcs(i, -1) = 0 (empty string)
Knapsack: knapsack(0, w) = 0 (no items)

Base cases prevent infinite recursion.
Worked Examples
// House Robber — LC 198
// H: rob(i) = max money robbing houses[i..n-1]
// I: two choices at house i:
//    rob it:  nums[i] + rob(i+2)
//    skip it: rob(i+1)
// B: rob(n) = 0  (no houses left)

int rob(int[] nums, int i) {
    if (i >= nums.length) return 0;          // BASE
    return Math.max(
        nums[i] + rob(nums, i+2),           // INDUCTION: rob i
        rob(nums, i+1)                       // INDUCTION: skip i
    );
}
// Call: rob(nums, 0)
// Next step: add memo[i] to eliminate repeated calls
// Climbing Stairs — LC 70
// H: climb(n) = number of ways to reach stair n
// I: last step was either 1 stair or 2 stairs
//    climb(n) = climb(n-1) + climb(n-2)
// B: climb(0) = 1 (empty path), climb(1) = 1

int climb(int n) {
    if (n == 0) return 1;   // BASE: empty path counts
    if (n == 1) return 1;   // BASE: one way to reach step 1
    return climb(n-1) + climb(n-2);   // INDUCTION
}
// Identical recurrence to Fibonacci — different interpretation
// Coin Change — LC 322
// H: minCoins(rem) = min coins to make exactly amount rem
// I: try each coin. After picking coin c:
//    need minCoins(rem - c) more coins
//    minCoins(rem) = 1 + min over all valid coins
// B: minCoins(0) = 0  (need 0 coins to make 0)

int minCoins(int[] coins, int rem) {
    if (rem == 0) return 0;          // BASE
    if (rem < 0)  return (int)1e9;   // impossible
    int best = (int)1e9;
    for (int coin : coins)
        best = Math.min(best, 1 + minCoins(coins, rem-coin)); // INDUCTION
    return best;
}
// Call: minCoins(coins, amount)
// Overlapping: minCoins(5) called from minCoins(7) and minCoins(6) etc → add memo!
// 0/1 Knapsack
// H: knapsack(i, w) = max value, first i items, capacity w
// I: two choices for item i:
//    skip: knapsack(i-1, w)
//    take: val[i] + knapsack(i-1, w - wt[i])   (if wt[i] <= w)
// B: knapsack(0, w) = 0  (no items)

int knapsack(int[] wt, int[] val, int i, int w) {
    if (i == 0 || w == 0) return 0;   // BASE
    int skip = knapsack(wt, val, i-1, w);   // INDUCTION: skip
    int take = 0;
    if (wt[i-1] <= w)
        take = val[i-1] + knapsack(wt, val, i-1, w-wt[i-1]);  // INDUCTION: take
    return Math.max(skip, take);
}
// Call: knapsack(wt, val, n, W)
// Two changing params (i, w) → 2D memo table
// LCS — LC 1143
// H: lcs(i, j) = LCS length of s1[0..i-1] and s2[0..j-1]
// I: if characters match → 1 + lcs(i-1, j-1)
//    else → max(lcs(i-1, j), lcs(i, j-1))  [skip from either]
// B: lcs(0, j) = 0  and  lcs(i, 0) = 0  (empty string)

int lcs(String s1, String s2, int i, int j) {
    if (i == 0 || j == 0) return 0;   // BASE
    if (s1.charAt(i-1) == s2.charAt(j-1))
        return 1 + lcs(s1, s2, i-1, j-1);   // MATCH
    return Math.max(
        lcs(s1, s2, i-1, j),    // skip from s1
        lcs(s1, s2, i, j-1)     // skip from s2
    );
}
// Call: lcs(s1, s2, s1.length(), s2.length())

The Overlap Test — Should you add memoization?
🔍 Simple test — draw a 3-level call tree

Pick a small input (n=5 or n=4). Draw the recursion tree 3 levels deep. Do any two nodes have the same arguments? If yes → overlapping subproblems → add memo.

fib(5): fib(3) appears twice at level 2 → ADD MEMO
merge sort(8): every subproblem is unique → no memo needed (D&C)
coin change(amount=5): minCoins(3) called from minCoins(4) AND minCoins(5) → ADD MEMO

✅ Rule: Always write recursion FIRST

Don't try to jump straight to the dp[] table. The recursive solution IS the DP — it's just unoptimised. Once you have correct recursion, memoization is 3 lines. Tabulation is a mechanical translation. The thinking happens at the recursion step.
