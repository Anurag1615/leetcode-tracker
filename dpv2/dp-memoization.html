💾 Memoization

Top-Down DP. Add a cache to your recursion — 3 lines of code, exponential → polynomial speedup.

💡 The 3-Line Memo Pattern

Every memoized solution follows the exact same structure:
1. Create memo table (size = changing parameters)
2. Check cache before computing: if (memo[i] != -1) return memo[i];
3. Compute, store, return: return memo[i] = recursion(...);

Step-by-Step: Adding Memo to House Robber
// Before memoization — O(2ⁿ)
int rob(int[] nums, int i) {
    if (i >= nums.length) return 0;
    return Math.max(
        nums[i] + rob(nums, i + 2),
        rob(nums, i + 1)
    );
}
// rob(3) computed from rob(1) AND rob(2)
// rob(5) computed: 2⁵ = 32 calls for n=5
// rob(50): 2⁵⁰ = 10¹⁵ calls — impossible
// After memoization — O(n)
int[] memo;

int rob(int[] nums) {
    memo = new int[nums.length];
    Arrays.fill(memo, -1);        // -1 = not computed yet
    return robHelper(nums, 0);
}

int robHelper(int[] nums, int i) {
    if (i >= nums.length) return 0;
    if (memo[i] != -1) return memo[i];   // ✅ CACHE HIT
    return memo[i] = Math.max(           // ✅ STORE THEN RETURN
        nums[i] + robHelper(nums, i + 2),
        robHelper(nums, i + 1)
    );
}
// Each robHelper(i) computed exactly once → O(n) total

Memo Rules — The Non-Negotiables
📐 Dimensions = Changing Parameters

Count the parameters that change between calls.
1 changing param → int[] memo = new int[n]
2 changing params → int[][] memo = new int[m][n]
The constant params (the full array, the coins list) are NOT state — they never change.

⚠️ Initialize to -1, NOT 0

If you initialize to 0 and 0 is a valid answer (common!), you get false cache hits.
Use -1 as "not computed yet".
Exception: if -1 is valid, use Integer.MIN_VALUE or a boolean[] computed array.

✅ Check BEFORE computing

Put the cache check as the FIRST thing after the base case — before any recursive calls or loops. Otherwise you do work before realizing it's cached.

🚫 Never memoize global state

The memo key must uniquely identify a subproblem. If your function modifies a list/array in place (like backtracking), you can't memoize — each call has different side effects.

Why does Memoization Work?
🔢 The math

Without memo: same subproblem computed exponentially many times → O(2ⁿ)
With memo: each unique subproblem computed exactly once

For 1D problems: there are n distinct subproblems (i from 0 to n) → O(n) time
For 2D problems: there are m×n distinct subproblems → O(m·n) time

The recursion tree might have 2ⁿ nodes, but with memo, each unique node is computed once and cached — all other "visits" are O(1) cache hits.
