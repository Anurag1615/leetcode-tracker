Why DP? — From Brute Force to Optimal
▾
🤔 The Core Problem with Recursion

Pure recursion recomputes the same subproblem exponentially many times. DP says: compute once, store the result, reuse.

Example: Fibonacci Call Tree for fib(5)

                        fib(5)
                       /       \
                  fib(4)        fib(3) ← computed AGAIN
                 /      \       /    \
            fib(3)    fib(2)  fib(2) fib(1)
            /    \    /   \    /   \
         fib(2) fib(1) fib(1) fib(0) fib(1) fib(0)
         /   \
      fib(1) fib(0)

fib(3) called 2 times, fib(2) called 3 times → T(n) = 2^n
With memoization: each fib(k) computed exactly once → T(n) = O(n)

The Two Conditions for DP

1️⃣ Overlapping Subproblems

The same subproblem appears multiple times in the recursion tree. Without caching: exponential work.

How to spot: Draw a small recursion tree. Do the same arguments appear twice?

2️⃣ Optimal Substructure

The optimal solution to the full problem can be built from optimal solutions of subproblems.

How to spot: Can you say "if I knew the best solution for a smaller input, I could compute the best for a larger one"?

DP vs Greedy vs Divide & Conquer

ApproachSubproblemsOverlap?Example
Dynamic ProgrammingOverlapping✅ Yes — cache resultsFibonacci, Knapsack
Divide & ConquerIndependent❌ No — no need to cacheMerge Sort, Binary Search
GreedyMakes local best choiceN/A — no subproblems storedHuffman, Activity Selection
🎯 Key Takeaway

Before applying DP, ask: "If I solve this recursively, do I re-solve the same subproblem?" If yes → DP. The memo table is just a cache. The recurrence is just the recursion. That's all DP is.

Step 1 — Think Recursively First (IBH Method)
▾
📐 IBH Method (Induction-Base-Hypothesis)

Never start with the DP table. Start by writing the recursive solution. Then memoize it. This approach works for 95% of DP problems.

Hypothesis — What does the function DO?
Assume your function solve(i) correctly returns the answer for input of size i. Don't think about HOW yet. Just define what it returns.
Example: int maxProfit(int[] prices, int i) returns max profit using prices[i..n-1]
Induction — How to solve for size i using size i-1?
If you already know the answer for i-1, how do you get the answer for i? This is your recurrence relation.
Example: for House Robber — either rob house i (skip i-1) or skip house i. dp[i] = max(dp[i-1], dp[i-2] + nums[i])
Base Case — Smallest input you can answer directly
What is the answer when i=0 or i=1 (no items / empty input)?
Example: dp[0]=nums[0], dp[1]=max(nums[0], nums[1])

Worked Example: House Robber (LC 198)

Step 1 — Pure Recursion (start here)
// HYPOTHESIS: rob(i) = max money robbing from house i to end
int rob(int[] nums, int i) {
    // BASE CASE: one house or no house
    if (i >= nums.length) return 0;

    // INDUCTION: two choices at every house
    int rob_i    = nums[i] + rob(nums, i+2); // rob house i, skip i+1
    int skip_i   = rob(nums, i+1);           // skip house i

    return Math.max(rob_i, skip_i);
}
// Call: rob(nums, 0)
// Problem: rob(2) called from rob(0) AND rob(1) → overlapping!
💡 The IBH Test — Is it recursive + overlapping?

Draw the call tree for nums=[1,2,3,1]:
rob(0) → rob(2) and rob(1)
rob(1) → rob(3) and rob(2)
rob(2) is called twice → overlapping subproblems → DP can help!

Step 2 — Add Memoization (Top-Down DP)
▾
🎯 The 3-Line Memo Pattern

Once you have the recursive solution, memoization is mechanical:
1. Create a memo table.   2. Check if already computed (return cached).   3. Compute, store, return.

// House Robber — Recursive → Memoized
int[] memo;

int rob(int[] nums) {
    memo = new int[nums.length];
    Arrays.fill(memo, -1);    // -1 = not computed yet
    return solve(nums, 0);
}

int solve(int[] nums, int i) {
    if (i >= nums.length) return 0;

    if (memo[i] != -1) return memo[i];  // ① CACHE HIT — return stored

    int take = nums[i] + solve(nums, i+2);
    int skip = solve(nums, i+1);

    return memo[i] = Math.max(take, skip);  // ② STORE THEN RETURN
}
// Time: O(n) — each state computed once
// Space: O(n) memo + O(n) call stack

// Coin Change — Recursive → Memoized
Map<Integer, Integer> memo = new HashMap<>();

int coinChange(int[] coins, int amount) {
    return solve(coins, amount);
}

int solve(int[] coins, int rem) {
    if (rem == 0) return 0;
    if (rem < 0) return Integer.MAX_VALUE;

    if (memo.containsKey(rem)) return memo.get(rem);  // CACHE HIT

    int minCoins = Integer.MAX_VALUE;
    for (int coin : coins) {
        int sub = solve(coins, rem - coin);
        if (sub != Integer.MAX_VALUE)
            minCoins = Math.min(minCoins, sub + 1);
    }

    memo.put(rem, minCoins);  // STORE
    return minCoins;
}

// LCS — 2D Memoization (two changing params → 2D table)
int[][] memo;

int lcs(String s1, String s2) {
    memo = new int[s1.length()+1][s2.length()+1];
    for (int[] row : memo) Arrays.fill(row, -1);
    return solve(s1, s2, s1.length()-1, s2.length()-1);
}

int solve(String s1, String s2, int i, int j) {
    if (i < 0 || j < 0) return 0;

    if (memo[i][j] != -1) return memo[i][j];  // CACHE HIT

    if (s1.charAt(i) == s2.charAt(j))
        return memo[i][j] = 1 + solve(s1, s2, i-1, j-1);  // MATCH

    return memo[i][j] = Math.max(             // NO MATCH
        solve(s1, s2, i-1, j),
        solve(s1, s2, i, j-1));
}
// Key: 2 changing params → 2D memo. N changing params → N-D memo.

// 0/1 Knapsack — 2D Memoization
int[][] memo;

int knapsack(int[] wt, int[] val, int W) {
    int n = wt.length;
    memo = new int[n][W+1];
    for (int[] row : memo) Arrays.fill(row, -1);
    return solve(wt, val, n-1, W);
}

int solve(int[] wt, int[] val, int i, int w) {
    if (i < 0 || w == 0) return 0;

    if (memo[i][w] != -1) return memo[i][w];

    int skip = solve(wt, val, i-1, w);
    int take = 0;
    if (wt[i] <= w)
        take = val[i] + solve(wt, val, i-1, w-wt[i]);

    return memo[i][w] = Math.max(skip, take);
}

The Memoization Rules

📐 Dimension = Changing Parameters

1 changing param (i) → 1D memo[]
2 changing params (i, j) → 2D memo[][]
3 changing params → 3D (usually over-thinking)

🚫 Don't Memoize on Objects

Memo key must be the changing parameters (indices, amounts). Never include the whole array or string — those are constants.

✅ Check Before Compute

Always check the cache BEFORE doing any recursive calls. Otherwise you waste time computing before realizing it's cached.

⚠️ Initialize to -1, Not 0

Use -1 (or INT_MIN) as "not computed". If valid answers include 0, using 0 as sentinel causes wrong cache hits.

Step 3 — Convert to Tabulation (Bottom-Up DP)
▾
🔄 Top-Down → Bottom-Up: The Conversion Recipe

Once you have working memoized code, converting to tabulation is mechanical — just reverse the direction.

Flip the direction
Recursion goes top→down (big to small). Tabulation goes bottom→up (small to big). Your loop order is the reverse of your recursion.
Replace recursive call with table lookup
solve(i-1) becomes dp[i-1]. solve(i-1, j) becomes dp[i-1][j]. Exact same recurrence, just reading from a table.
Seed the base cases first
Whatever your recursion's base case returned, hard-code that into the dp[] table before the loop starts.
Try to drop a dimension
If dp[i] only depends on dp[i-1] and dp[i-2], use two variables instead of an array. If dp[i][j] only needs row i-1, use one 1D array (rolling array).

// House Robber — Memo → Tabulation → Space Optimised

// 1. Tabulation (1D array)
int rob1(int[] nums) {
    int n = nums.length;
    if (n == 1) return nums[0];
    int[] dp = new int[n];
    dp[0] = nums[0];                           // BASE CASE 1
    dp[1] = Math.max(nums[0], nums[1]);        // BASE CASE 2
    for (int i = 2; i < n; i++)
        dp[i] = Math.max(dp[i-1], dp[i-2] + nums[i]);  // RECURRENCE
    return dp[n-1];
}

// 2. Space Optimised → O(1) (dp[i] only needs dp[i-1] and dp[i-2])
int rob2(int[] nums) {
    int prev2 = 0, prev1 = 0;
    for (int num : nums) {
        int curr = Math.max(prev1, prev2 + num);
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}

// Coin Change — Tabulation
int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount+1];
    Arrays.fill(dp, amount+1);  // sentinel: impossible value
    dp[0] = 0;                  // BASE: 0 coins to make 0

    for (int i = 1; i <= amount; i++)
        for (int coin : coins)
            if (coin <= i)
                dp[i] = Math.min(dp[i], dp[i-coin] + 1);  // RECURRENCE

    return dp[amount] > amount ? -1 : dp[amount];
}
// Compare with memo: same recurrence, just loops instead of recursion
// dp[i-coin] replaces solve(coins, i-coin)

// Knapsack — 2D Tabulation → 1D Rolling Array

// 1. Full 2D table O(n*W) space
int knap2D(int[] wt, int[] val, int W) {
    int n = wt.length;
    int[][] dp = new int[n+1][W+1];
    for (int i = 1; i <= n; i++)
        for (int w = 1; w <= W; w++) {
            dp[i][w] = dp[i-1][w];         // SKIP
            if (wt[i-1] <= w)
                dp[i][w] = Math.max(dp[i][w], dp[i-1][w-wt[i-1]] + val[i-1]);
        }
    return dp[n][W];
}

// 2. 1D rolling array O(W) space — iterate W in REVERSE for 0/1
int knap1D(int[] wt, int[] val, int W) {
    int[] dp = new int[W+1];
    for (int i = 0; i < wt.length; i++)
        for (int w = W; w >= wt[i]; w--)  // REVERSE = 0/1 (each item once)
            dp[w] = Math.max(dp[w], dp[w-wt[i]] + val[i]);
    return dp[W];
}
// Change reverse → forward for Unbounded Knapsack (reusable items)

Intuition — What Is Dynamic Programming?
▾
🧠 One-line definition

DP = Recursion + Memoization. If a recursive solution recomputes the same subproblem multiple times, cache the result. That's it.

The Three Properties of a DP Problem

1️⃣ Optimal Substructure

Optimal solution to the problem can be built from optimal solutions to subproblems.

2️⃣ Overlapping Subproblems

Same subproblems are solved multiple times. Without memoization: exponential. With: polynomial.

3️⃣ No Aftereffect

Future decisions depend only on the current state, not how you got there.

Recursion → Memoization → Tabulation

Fibonacci — 3 ways
// 1. Pure Recursion — O(2^n) ❌
int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);   // fib(3) computed 100s of times
}

// 2. Top-Down Memoization — O(n) ✅
int[] memo = new int[n+1];
Arrays.fill(memo, -1);
int fib(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];       // cache hit
    return memo[n] = fib(n-1) + fib(n-2);   // store before return
}

// 3. Bottom-Up Tabulation — O(n) ✅ (no recursion overhead)
int fib(int n) {
    if (n <= 1) return n;
    int[] dp = new int[n+1];
    dp[0] = 0; dp[1] = 1;
    for (int i = 2; i <= n; i++)
        dp[i] = dp[i-1] + dp[i-2];
    return dp[n];
}

// 4. Space Optimised — O(1) ✅✅
int fib(int n) {
    int a = 0, b = 1;
    for (int i = 2; i <= n; i++) { int c = a+b; a = b; b = c; }
    return b;
}
Top-Down (Memoization)

Write the recursion first, add a memo table. Natural — same structure as brute force. Good for: complex state, sparse subproblems.

Bottom-Up (Tabulation)

Fill a dp[] table iteratively from base cases. No stack overflow risk. Good for: dense subproblems, space optimisation.

Identify the Pattern — Which DP Type Is This?
▾
🔍 Ask these 3 questions first

1. Can I split the problem into smaller versions of itself? (substructure)
2. Do I recompute the same state multiple times? (overlapping)
3. Can I express the answer as dp[state] = f(dp[smaller states])?
If YES to all → it's DP.

5-Step Template — Solve Any DP Problem
▾
Universal DP Framework

Every DP problem follows the same 5 steps. Master this, and any problem becomes a fill-in-the-blank exercise.

Define the State
What does dp[i] or dp[i][j] represent? Be precise.
Knapsack: dp[i][w] = max value using first i items with capacity w.
LCS: dp[i][j] = LCS length of s1[0..i] and s2[0..j].
Identify Base Cases
What are the trivially known states?
Fibonacci: dp[0]=0, dp[1]=1.
Grid DP: first row and column have only one path.
Write the Recurrence
How does dp[i] depend on previous states? This is the core step.
Knapsack: dp[i][w] = max(dp[i-1][w], dp[i-1][w-wt[i]] + val[i])
LCS: dp[i][j] = dp[i-1][j-1]+1 if match, else max(dp[i-1][j], dp[i][j-1])
Decide Fill Order
Ensure that when you compute dp[i], all dependencies are already computed.
Usually: left-to-right, top-to-bottom. For interval DP: by increasing length.
Extract Answer + Optimise Space
Where is the answer in the table? Often dp[n] or dp[n][W].
Then: can you reduce 2D → 1D by only keeping the previous row? Many problems go O(n²) → O(n) space.

Template in Code (0/1 Knapsack)

Java — 5 steps annotated
int knapsack(int[] wt, int[] val, int W) {
    int n = wt.length;

    // STEP 1: Define state — dp[i][w] = max value, first i items, capacity w
    int[][] dp = new int[n+1][W+1];

    // STEP 2: Base cases — dp[0][*] = 0 (no items), dp[*][0] = 0 (no capacity)
    // Arrays.fill handles this (Java zeroes by default)

    // STEP 3+4: Recurrence + fill order (i from 1..n, w from 1..W)
    for (int i = 1; i <= n; i++) {
        for (int w = 1; w <= W; w++) {
            dp[i][w] = dp[i-1][w];                        // skip item i
            if (wt[i-1] <= w)
                dp[i][w] = Math.max(dp[i][w],
                    dp[i-1][w-wt[i-1]] + val[i-1]);       // take item i
        }
    }

    // STEP 5: Answer at dp[n][W]
    return dp[n][W];

    // Space optimisation: use 1D dp[W+1], iterate w from W down to wt[i-1]
}
💡 Top-Down vs Bottom-Up — When to use which

Top-Down: Easy to write (just add memo to recursion). Better when state space is sparse (many states never visited).
Bottom-Up: No recursion overhead, easier space optimisation. Better for dense state spaces like grid DP or knapsack.

♾️ Unbounded Knapsack
AV Playlist 2
Same item usable unlimited times. Iterate weights FORWARD (not reverse). Rod Cutting, Coin Change.
Time: O(n·W) · Space: O(W)
Java — Core Pattern
// Unbounded — iterate w forward (same item can be reused)
int[] dp = new int[W+1];
for (int i = 0; i < n; i++)
    for (int w = wt[i]; w <= W; w++)   // FORWARD = reuse allowed
        dp[w] = Math.max(dp[w], dp[w-wt[i]] + val[i]);

// ── Coin Change (min coins) ──
int[] dp = new int[amount+1];
Arrays.fill(dp, amount+1);
dp[0] = 0;
for (int coin : coins)
    for (int j = coin; j <= amount; j++)
        dp[j] = Math.min(dp[j], dp[j-coin] + 1);
return dp[amount] > amount ? -1 : dp[amount];

// ── Coin Change II (count ways) ──
long[] dp = new long[amount+1];
dp[0] = 1;
for (int coin : coins)
    for (int j = coin; j <= amount; j++)
        dp[j] += dp[j-coin];  // combinations (outer loop = coins)
return dp[amount];

🌿 Fibonacci / 1D DP
AV Playlist 3
dp[i] depends only on dp[i-1] and dp[i-2]. Covers stair climbing, house robber, decode ways.
Time: O(n) · Space: O(1) after optimisation
Java — Core Pattern
// House Robber — classic 1D DP
int rob(int[] nums) {
    int prev2 = 0, prev1 = 0;
    for (int num : nums) {
        int curr = Math.max(prev1, prev2 + num);
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}

// Decode Ways — Fibonacci variant
int numDecodings(String s) {
    int n = s.length();
    int[] dp = new int[n+1];
    dp[0] = 1;
    dp[1] = s.charAt(0) != '0' ? 1 : 0;
    for (int i = 2; i <= n; i++) {
        int one = s.charAt(i-1) - '0';
        int two = Integer.parseInt(s.substring(i-2, i));
        if (one != 0) dp[i] += dp[i-1];
        if (two >= 10 && two <= 26) dp[i] += dp[i-2];
    }
    return dp[n];
}

🔡 LCS & Variants
AV Playlist 4
2D dp: dp[i][j] = LCS length of s1[0..i] and s2[0..j]. Match → diagonal+1, else max(skip either).
Time: O(m·n) · Space: O(n)
Java — Core Pattern
// Longest Common Subsequence
int lcs(String s1, String s2) {
    int m = s1.length(), n = s2.length();
    int[] dp = new int[n+1];
    for (int i = 1; i <= m; i++) {
        int prev = 0;
        for (int j = 1; j <= n; j++) {
            int temp = dp[j];
            if (s1.charAt(i-1) == s2.charAt(j-1))
                dp[j] = prev + 1;       // diagonal
            else
                dp[j] = Math.max(dp[j], dp[j-1]);
            prev = temp;
        }
    }
    return dp[n];
}

// Edit Distance — 1 extra op type
int editDistance(String s, String t) {
    int m = s.length(), n = t.length();
    int[][] dp = new int[m+1][n+1];
    for (int i=0;i<=m;i++) dp[i][0]=i;
    for (int j=0;j<=n;j++) dp[0][j]=j;
    for (int i=1;i<=m;i++)
        for (int j=1;j<=n;j++)
            dp[i][j] = s.charAt(i-1)==t.charAt(j-1) ? dp[i-1][j-1]
                : 1 + Math.min(dp[i-1][j-1], Math.min(dp[i-1][j], dp[i][j-1]));
    return dp[m][n];
}
💡 Key Insight

LCS → LPS (Longest Palindromic Subsequence) = LCS(s, reverse(s)). LCS → Edit Distance adds replace op.

// O(n²) DP
int lengthOfLIS(int[] nums) {

    int[] dp = new int[n];
    Arrays.fill(dp, 1);

        for (int j = 0; j < i; j++)

}

// O(n log n) Patience Sort (tails array)
int lisOptimal(int[] nums) {
    List tails = new ArrayList<>();
    for (int num : nums) {
        int pos = Collections.binarySearch(tails, num);
        if (pos < 0) pos = -(pos+1);
        if (pos == tails.size()) tails.add(num);
        else tails.set(pos, num);
    }
    return tails.size();
}

⚡ Kadane's Algorithm
AV Playlist 6
Greedy DP: extend or restart. dp[i] = max(nums[i], dp[i-1] + nums[i]). O(n) time O(1) space.
Time: O(n) · Space: O(1)
Java — Core Pattern
// Classic Kadane's
int maxSubarray(int[] nums) {
    int maxSum = nums[0], curr = nums[0];
    for (int i = 1; i < nums.length; i++) {
        curr = Math.max(nums[i], curr + nums[i]);  // extend or restart
        maxSum = Math.max(maxSum, curr);
    }
    return maxSum;
}

// Maximum Product Subarray — track min too (negatives flip)
int maxProduct(int[] nums) {
    int maxP = nums[0], minP = nums[0], res = nums[0];
    for (int i = 1; i < nums.length; i++) {
        if (nums[i] < 0) { int t = maxP; maxP = minP; minP = t; }
        maxP = Math.max(nums[i], maxP * nums[i]);
        minP = Math.min(nums[i], minP * nums[i]);
        res  = Math.max(res, maxP);
    }
    return res;
}

// Maximum Sum Circular Subarray
int maxSumCircular(int[] nums) {
    int total=0, maxSum=nums[0], curMax=0, minSum=nums[0], curMin=0;
    for (int n : nums) {
        curMax = Math.max(curMax+n, n); maxSum = Math.max(maxSum, curMax);
        curMin = Math.min(curMin+n, n); minSum = Math.min(minSum, curMin);
        total += n;
    }
    return maxSum > 0 ? Math.max(maxSum, total-minSum) : maxSum;
}
💡 Key Insight

Circular max = max(normal Kadane, total − min subarray). If all negative, return normal Kadane result.

// Matrix Chain Multiplication
int mcm(int[] dims) {
    int n = dims.length - 1;
    int[][] dp = new int[n][n];
    // Fill by length of chain

        for (int i = 0; i <= n-len; i++) {

    }
    return dp[0][n-1];
}

🌳 DP on Trees
AV Playlist 8
Process postorder (children first). Return pair [rob, skip] or [include, exclude] from each subtree.
Time: O(n) · Space: O(h) recursion stack
Java — Core Pattern
// House Robber III — return [rob, skip] pair
int[] robTree(TreeNode node) {
    if (node == null) return new int[]{0, 0};
    int[] left  = robTree(node.left);
    int[] right = robTree(node.right);
    // rob this node: can't rob children
    int rob  = node.val + left[1] + right[1];
    // skip this: children can be robbed or not
    int skip = Math.max(left[0], left[1]) + Math.max(right[0], right[1]);
    return new int[]{rob, skip};
}
// Call: int[] res = robTree(root); return Math.max(res[0], res[1]);

// Diameter of Binary Tree
int ans = 0;
int depth(TreeNode node) {
    if (node == null) return 0;
    int L = depth(node.left), R = depth(node.right);
    ans = Math.max(ans, L + R);  // path through this node
    return 1 + Math.max(L, R);  // return height
}

int maxProfitCooldown(int[] prices) {

        hold = Math.max(hold, cash - p);
    }
    return cash;
}

Common Mistakes — What Beginners Get Wrong
▾
⚠️ These mistakes cause 80% of DP bugs

Read each one carefully — most DP interview failures come from these patterns.

❌ Mistake 1 — Wrong iteration direction in 1D knapsack
// WRONG: iterating forward for 0/1 knapsack (same item used multiple times!)
for (int w = wt[i]; w <= W; w++)  dp[w] = Math.max(dp[w], dp[w-wt[i]] + val[i]);
// CORRECT: iterate backward for 0/1 (each item used once)
for (int w = W; w >= wt[i]; w--)  dp[w] = Math.max(dp[w], dp[w-wt[i]] + val[i]);

Rule: 0/1 = backward, Unbounded = forward. The direction controls reuse.

❌ Mistake 2 — Using 0 as memo sentinel when 0 is a valid answer
int[] memo = new int[n];  // initialized to 0
// BUG: when dp[i]=0 is valid answer, treated as "not computed"!
Arrays.fill(memo, -1);  // -1 is never a valid answer for most problems
❌ Mistake 3 — Forgetting to copy array before adding to result
result.add(path);          // BUG: adds reference — path will change later!
result.add(new ArrayList<>(path));  // always copy mutable collections
❌ Mistake 4 — Off-by-one in dp table size
int[] dp = new int[n];     // BUG for Fibonacci: needs index n, so size n+1
int[] dp = new int[n+1];   // dp[0..n] inclusive

Rule: if dp[n] is the answer, allocate n+1. If dp[n-1], allocate n.

❌ Mistake 5 — Not handling all base cases
// House Robber II (circular array) — student only runs rob() once
return rob(nums);          // WRONG: misses the circular constraint
// Must run rob() on two sub-arrays: [0,n-2] and [1,n-1]
return Math.max(rob(nums, 0, n-2), rob(nums, 1, n-1));
❌ Mistake 6 — Confusing "count ways" vs "min/max" recurrence

Count ways: dp[i] += dp[i-x]  (accumulate all ways)
Min/Max: dp[i] = Math.min(dp[i], dp[i-x]+1)  (keep best)
Exists: dp[i] |= dp[i-x]  (boolean OR)
Same recurrence structure, different operator — mix them up → wrong answer.

❌ Mistake 7 — Wrong loop order for Combination Sum IV (ordered)
// Gives COMBINATIONS (unordered) — wrong for LC 377
for (int coin : coins)
    for (int j = coin; j <= amount; j++)  dp[j] += dp[j-coin];
// Gives PERMUTATIONS (ordered) — correct for LC 377
for (int j = 1; j <= amount; j++)
    for (int coin : coins)
        if (j >= coin)  dp[j] += dp[j-coin];

Coins outer → unordered combinations. Amounts outer → ordered permutations.

❌ Mistake 8 — Not considering all transition options in state machine DP

Stock with cooldown: forgetting the rest state. Forgetting that after selling you CANNOT buy next day. Always enumerate ALL states and ALL transitions explicitly before coding.

How to Present DP in an Interview

Brute force first — always
Say: "Let me start with the recursive brute force." Write the recursion without worrying about efficiency. Interviewers want to see your thinking.
Identify overlapping subproblems
Say: "I see that this subproblem is being recomputed. Let me add memoization." Add a memo table — now you have top-down DP.
Convert to tabulation if asked
Say: "To avoid recursion overhead, I can build this bottom-up." Reverse the direction, seed base cases, fill the table.
Optimise space — always mention it
Even if you don't code it, say: "I can reduce to O(1)/O(n) space by only keeping the previous row/two variables." This shows depth.

Common DP Tricks

🔄 Reverse Iteration (0/1 Knapsack)

Iterate j from W down to wt[i]. This prevents reusing the same item in one pass. Forward = unbounded, reverse = 0/1.

📐 Interval DP Fill Order

Always fill by increasing length: for len=2..n, i=0..n-len, j=i+len-1. Ensures sub-intervals filled before larger ones.

🗜 Space Optimisation

If dp[i] only needs dp[i-1], use two variables. If dp[i][j] needs only row i-1, use 1D rolling array. O(n²) → O(n).

🎯 Identify Min/Max vs Count

Count ways → add (+=). Min/Max → Math.min/max. Exist → boolean OR (|=). Same recurrence, different operator.

🌳 Tree DP Return Pair

Don't try to compute in one pass. Return int[]{include, exclude} from each node. Parent combines both options.

💱 When to Switch Recursion → DP

If backtracking has overlapping subproblems (same args called multiple times) → memoize. If all subproblems needed → tabulate.

Quiz — Can You Identify the DP Pattern?
▾
Q1 / 8
"Given a rod of length n and prices for each length, find the maximum obtainable price." — Which DP pattern?
✅ Unbounded Knapsack. Each piece length can be cut unlimited times (unbounded). Lengths = weights, prices = values, rod length = capacity. Iterate forward in inner loop.
Q2 / 8
dp[i][j] = LCS(s1[0..i], s2[0..j]). If s1[i] == s2[j], what is dp[i][j]?
✅ dp[i-1][j-1] + 1. When characters match, the LCS extends by 1 from the state before both characters (diagonal). When they don't match: max(skip from s1, skip from s2) = max(dp[i-1][j], dp[i][j-1]).
Q3 / 8
For Coin Change (LC 322), should the inner loop iterate FORWARD or BACKWARD? Why?
✅ Forward. Coin Change = Unbounded Knapsack (each coin reusable). Forward iteration: when computing dp[j], dp[j-coin] already includes the current coin, allowing it to be used again. Backward = 0/1 knapsack where each coin used at most once.
Q4 / 8
You're solving Burst Balloons (LC 312). A student sets up: dp[i][j] = max coins bursting balloons i..j, splitting at k as the FIRST balloon to burst. What's wrong?
✅ Key Burst Balloons insight: if k is the FIRST balloon, then neighbours of dp[i][k-1] and dp[k+1][j] depend on what k's neighbours were — making subproblems NOT independent. If k is the LAST, then when computing dp[i][k-1], k is still present as a boundary — subproblems become independent.
Q5 / 8
LIS can be solved in O(n log n). What data structure makes this possible?
✅ Patience Sorting / Tails array. tails[i] = smallest ending element of all increasing subsequences of length i+1. For each new element: binary search for first tail ≥ element, replace it. Size of tails = LIS length. This is O(n log n).
Q6 / 8
Stock problem: "You can complete at most 2 transactions." How many states do you need?
✅ 4 states: buy1 = max profit after first buy, sell1 = after first sell, buy2 = after second buy, sell2 = after second sell. Transitions: buy1=max(buy1,−price), sell1=max(sell1,buy1+price), buy2=max(buy2,sell1−price), sell2=max(sell2,buy2+price). Answer = sell2.
Q7 / 8
When should you use Bitmask DP instead of regular DP?
✅ Bitmask DP when: (1) you need to track which subset of items has been processed, (2) n ≤ 20 making 2ⁿ states feasible. Classic: TSP (which cities visited), assignment problems, set cover. State = (current_position, visited_bitmask).
Q8 / 8
The space-optimised LCS uses a 1D array. When computing dp[j] for row i, you need the diagonal value dp[i-1][j-1]. How do you preserve it?
✅ Save prev = dp[j] BEFORE overwriting it: int temp=dp[j]; dp[j]=...(use prev as diagonal)...; prev=temp;. This way prev holds the OLD dp[j] which equals dp[i-1][j-1] relative to current position. Classic 1D LCS optimisation.
